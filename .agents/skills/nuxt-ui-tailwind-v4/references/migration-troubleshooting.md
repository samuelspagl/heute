# Migration and troubleshooting

## From Tailwind v3 or `@nuxtjs/tailwindcss`

- Inspect `package.json`, `nuxt.config.ts`, `tailwind.config.js/ts`, `postcss.config.js`, existing global CSS, and CSS generated by modules.
- Check whether `@nuxtjs/tailwindcss` is required by other modules. The Nuxt UI v4 documentation's preferred setup uses `@nuxt/ui` + `tailwindcss` v4 directly. Do not assume two Tailwind integrations are necessary.
- Move relevant `theme.extend` custom values into CSS-first `@theme` tokens where appropriate. A complete migration may also need changes to custom plugins and content scanning.
- Replace v3 directives (`@tailwind base; @tailwind components; @tailwind utilities;`) with `@import "tailwindcss";` for the v4 pipeline.
- Add `@import "@nuxt/ui";` *after* Tailwind import. Ensure this is imported once from the configured main stylesheet.
- Update obsolete Nuxt UI v3 theme keys to the v4 variant/slot structure (check current component source/docs).

## Symptom: UI components appear unstyled

1. Is `@nuxt/ui` registered in `modules`?
2. Is main CSS listed in Nuxt `css` and resolving to the correct path?
3. Are both CSS imports present, in the correct order?
4. Is another stylesheet or duplicate Tailwind module overriding the layers?
5. Did a production build fail to discover dynamic utilities?

## Symptom: custom `primary` color does not appear

1. Did `@theme` define the custom palette *with enough shades* (`--color-brand-50...950`)?
2. Did `app/app.config.ts` map `ui.colors.primary` to `'brand'` (without `--color-` prefix)?
3. Is the app config file in the correct directory for the installed Nuxt version?
4. Is a `--ui-primary` direct override intentionally bypassing palette-based colors?
5. Are light and dark color modes both correct?

## Symptom: overlays or toasts do not work

Ensure the application root is wrapped with `<UApp>`. Avoid multiple competing providers. Also verify teleports are not hidden behind high-z-index glass overlays or clipped containers.

## Symptom: hydration mismatch

Do not render different server/client DOM trees based on `window.matchMedia` in setup. Keep SSR HTML stable, and use CSS for media/color-mode differences. Defer browser-specific effects to onMounted / `<ClientOnly>` for genuine client-only features.

## Validate

Run project-specific lint/typecheck/build/test commands, inspect the CSS in a production preview, confirm focus-visible styles, keyboard navigation, and consistent light/dark backgrounds on first load.
